## 二、P0 · 阻断级缺陷（必须先修，否则一切都是空谈）

### P0-1　工程当前**无法编译**：`ClickOutcome.ok` 不存在（3 处）

`EngineBridge.ClickOutcome` 声明的字段只有 `clicked / failure / detail`：

```kotlin
// EngineBridge.kt:187
data class ClickOutcome(
    val clicked: Boolean,
    val failure: StzbUiMatcher.ButtonLookupFailure?,
    val detail: String
)
```

而有 `ok` 的是**另一个类** `ClickAndExpect`（返回自 `clickAndExpect()`）：

```kotlin
// EngineBridge.kt:327
val ok: Boolean get() = clicked && sceneReached
```

三处把 `clickButtonDiagnosed()`（返回 `ClickOutcome`）的返回值当 `ClickAndExpect` 用了：

| 文件:行 | 代码 | 影响的痛点 |
|---------|------|------------|
| `tactics/TacticalPipeline.kt:249` | `if (!confirmRes.ok)` | **痛点 3 挂牌到点出征主链路** |
| `tactics/DailyLogisticsFlow.kt:196` | `if (!recruitAction.ok)` | 痛点 4 预备役补兵 |
| `tactics/AccurateFarmingFlow.kt:246` | `if (!confirmAction.ok)` | 痛点 5 屯田下发 |

**后果**：`Unresolved reference: ok` → `assembleDebug` / `assembleRelease` 直接失败 → **产不出 APK，五大痛点一条都跑不起来**。

**修法**（三选一）：
```kotlin
// 方案 A（最小改动，语义等价）
if (!confirmRes.clicked) { ... }
// 方案 B（更严谨：既看是否点到，也看场景是否跳转）
val r = EngineBridge.clickAndExpect(ButtonType.CONFIRM, GameState.MAIN_MAP, 3000L, 2)
if (!r.ok) { ... }
```
> 已在 `tools/` 下补了同类扫描脚本，可当作新增的静态闸门（见 §五 建议 1）。

### P0-2　缺 `SCHEDULE_EXACT_ALARM` 权限，「RTC 硬件级定时唤醒」在 Android 12+ 失效

`AndroidManifest.xml` 现有权限：`SYSTEM_ALERT_WINDOW / FOREGROUND_SERVICE(_MEDIA_PROJECTION) / VIBRATE / WAKE_LOCK / INTERNET / ACCESS_NETWORK_STATE / POST_NOTIFICATIONS`。

**没有** `SCHEDULE_EXACT_ALARM`（或 `USE_EXACT_ALARM`），但：

```kotlin
// ScheduledTaskManager.kt:447
alarmManager.setExactAndAllowWhileIdle(AlarmManager.RTC_WAKEUP, nextTriggerMs, pendingIntent)
...
} catch (e: SecurityException) {
    Log.w(TAG, "系统缺少精确闹钟权限，继续依赖协程轮询调度: ${e.message}")  // ← 被静默吞掉
}
```

在 `targetSdk 34` 上，无 `SCHEDULE_EXACT_ALARM` 时该调用**必然抛 `SecurityException`**，
被 `catch` 吞掉后只剩 `delay(15000)` 的协程轮询 —— 而协程在 Doze 深度息屏下会被挂起。

**后果**：痛点 3 最核心的卖点「手机硬件 RTC 芯片强行唤醒 CPU、零漂移」**实际不成立**；
深度息屏后定时任务不会准点触发（这正是它宣称要解决的那个痛点）。

**修法**：
1. Manifest 增加（`<manifest>` 内，与其它 uses-permission 同级）：
```xml
<uses-permission android:name="android.permission.SCHEDULE_EXACT_ALARM" />
```
2. 运行时引导用户授予「闹钟与提醒」特殊权限：
```kotlin
if (Build.VERSION.SDK_INT >= 31 && !alarmManager.canScheduleExactAlarms()) {
    startActivity(Intent(Settings.ACTION_REQUEST_SCHEDULE_EXACT_ALARM))
}
```
3. 把 `catch (SecurityException)` 从"只打日志"改为**回传 UI 提示 + 引导授权**，不要静默降级。

## 三、P1 · 逻辑坑（会导致功能名不副实或行为异常）

### P1-1　AutoPilot 与 Pipeline 的任务类型不一致 → 5 分钟微保活永不触发

| 位置 | 代码 | 实际值 |
|------|------|--------|
| `TacticalPipeline.kt:312 / 321` | `launchTask(TaskType.NIGHT_SENTINEL)` | `NIGHT_SENTINEL` |
| `AutoPilot.kt:260` | `pipeline.currentTaskType == TacticalState.TaskType.RAID_DEFENSE` | 永远为 `false` |

`TacticalPipeline` 里 `startRaidDefense()` 与 `startNightSentinel()` **都**写入 `NIGHT_SENTINEL`，
**没有任何路径**会把 `activeTaskType` 设成 `RAID_DEFENSE`。于是 AutoPilot 的 `patrolAlive` 恒为 `false`：

```kotlin
val needsRestart = !raidDispatched || (!patrolAlive && nowMs - raidLastStartAtMs >= 60_000L)
```

在 `ALERT_RAID_ACTIVE` 分支下，每满 60 秒就会 `startRaidDefense()` →
`launchTask()` → 先 `stopCurrentTask()` 拆掉正在跑的哨兵，再重建。而 `startPatrol()` 每次都会：

```kotlin
lastKeepAliveTimeMs = System.currentTimeMillis()   // ← 每 60s 归零一次
```

保活周期是 5 分钟，却每 60 秒被重置一次 → **`performKeepAliveJiggle()` 永远不会被执行**，
痛点 1 的「防掉线微保活」实际失效。

**修法**：两边统一。建议把 `TacticalPipeline` 的 `startRaidDefense` 也改回 `RAID_DEFENSE`，
或把 `AutoPilot.kt:260` 改为同时接受两种类型：
```kotlin
val patrolAlive = pipeline.currentTaskType == TacticalState.TaskType.RAID_DEFENSE ||
                  pipeline.currentTaskType == TacticalState.TaskType.NIGHT_SENTINEL
```

### P1-2　痛点 4「免费税收完毕自动熔断防误点扣玉」**未实现**

`LogisticsConfig.maxDailyTaxTimes` **声明后在整个工程内零引用**（已全仓库 grep 确认）：

```kotlin
// DailyLogisticsFlow.kt:36
val maxDailyTaxTimes: Int = 3,      // ← 死字段
```

实际 `performTaxLevy()` 的行为是：点主城 → 找 `TAX` 按键（`primaryKeyword="税收"`，别名含 **"强征"**）→
点它 → 再"看到 `CONFIRM` 就点"。

而 `ButtonType.TAX` 的别名表是：
```kotlin
TAX("税收", listOf("征税", "强征", "征 税", "税额", "课税"))
```
**"强征"通常就是消耗玉符/元宝的付费征税**。脚本无法区分免费/付费，
"看到就点 + 看到确定就点" → **确实存在误点付费征税、扣掉玩家玉符的风险**。
宣称的"熔断防误点扣玉"完全没有代码。

**修法**：在 `performTaxLevy` 中增加"免费额度/付费标识"判定（OCR 该按钮附近是否出现"玉/元宝/付费"字样），
命中即放弃本轮；并把 `maxDailyTaxTimes` 真正接上计数器（持久化到 SharedPreferences）。

## 四、P2 · 工具链 / 资产 / 授权

### P2-1　一键回归脚本会被"缺 PyYAML"中途打断（易造成"假绿")

实测：
```
python tools/run_all_checks.py
  → PASS | refs / refs-selftest / native-ocr / native-ocr-selftest
  → 需要 PyYAML：pip install pyyaml        ← check_ci_shell.py 在 import 期 sys.exit(2)
  → 输出中断，退出码 2
```
`check_ci_shell.py` 顶部做了 `except ImportError: sys.exit(2)`，
而 `run_all_checks.py` 是**在循环里 importlib 加载**各校验器 —— `SystemExit` 会打断整条编排，
表现为"跑了一半就停"，很容易被误读为"只跑到第 4 项就都过了"。

用带 PyYAML 的解释器（本机 `C:\Program Files\python\python.exe`，PyYAML 5.3.1）实跑，
才是完整的 **18 PASS / 0 FAIL / 1 SKIP**：
```
PASS | refs … native-ocr-selftest … ci-shell … license-token … coord-math …
      timing-math … decision-logic … watchdog-logic … sentinel-logic …
      siege-sync … schedule-manager … logistics-farming … asset-budget …
      model-bases … acceptance-selftest
SKIP | scene-fingerprint（需真机截图）
```

### P2-2　`verify_refs.py` 的"成员对账"覆盖不到数据类属性 → 掩盖了 P0-1

该脚本的成员对账规则是 `\b<对象>\.(<枚举类型>)\.([A-Za-z_]\w*)` 形式 ——
**只校验枚举常量**（`ButtonType.X` / `TaskType.X` / `GameState.X` …），
不校验 `局部变量.属性`。所以 3 处 `ClickOutcome.ok` 一路绿灯。

### P2-3　模型资产未入包，多项能力静默降级

`client/app/src/main/assets/models/` 只有 2 个文件：`README.md` + `slg_knowledge_vector_hnsw.bin`（21 KB）。
仓库根 `.models/` 里虽有 bge / rbt3 / yolov8 / PP-OCRv4 ONNX，但**未打进 APK**（`p00_ROADMAP` 也标注 `pipeline/rate_of_land.json` ❌ 不打进 APK）。

`tools/p1/check_assets.py` 实测缺失：
```
❌ models/yolov8n_stzb.bin / .param      → YOLO 视觉检测不可用
❌ models/bge_zh_int8.onnx + vocab.txt   → useBge=false，RAG 退化为 64 维哈希向量
❌ models/intent_slot_zh.onnx + vocab    → 意图槽位模型不可用
❌ ch_PP-OCRv4_*                          → 仍在用 PP-OCRv3
✅ ch_PP-OCRv3_* (6 个)                   → OCR 主体资产齐备

```
